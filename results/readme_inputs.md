# README inputs: where every README number comes from

This is an audit for the final README, not the README itself. Each section names the script that generates its numbers and the saved results it reads. No numbers are copied here (Rules 15, 22).

The section list is the PRD §10 "README" deliverable: question, feature ablation, head comparison with CIs, LIVE-VQC, gap to SOTA, limitations, what was not done, then the demo. PRD §9 ("Realistic End State") holds expectations rather than sections, so its four statements are checked as claims in §10 below. **Gaps** at the end list every README claim with no generated source yet.

## Gaps: README claims with no generated source yet

1. **Published SOTA numbers** (Rule 21). No file holds the cited KoNViD-1k / LIVE-VQC numbers, their papers, splits and protocols, or the reasons for the gap. This needs a committed citation table (for example `results/sota.csv` with paper, split, protocol and metric) before any comparison is written.
2. **Inner-validation overlap size** (Rule 1). The overlap is disclosed in RULES/DECISIONS, but no script counts how many inner-validation videos are test videos in other folds. This matters only if the README states a count or fraction.
3. **Dataset licenses** (Rule 5). No saved license check for KoNViD-1k / LIVE-VQC exists in `results/`, and one is required before publishing.
4. **Run instructions in the repo.** The operations docs are local-only, so the README must carry the build and run steps itself. The clean-machine test found steps missing from the documented path; see the "undocumented" rows in `results/phase4/clean_build.md`.
5. **Phase 4b gate currency.** The committed gate binds the image and sources from its last report run. Tasks 2 and 4 later changed `serving/app.py`, `src/serving_bundle.py` and `DECISIONS.md`, so the gate must be rerun on the final image before the README cites it.
6. **Deployed-row seed wording.** `results/phase3/deployment.json` has `seed: null` and `live_five_seed: null` because the deployed ridge is deterministic. The README should say "single deterministic fit", not show a five-seed summary for it; Rule 9/28's seed-0 wording applies to neural heads.
