# Rules

These rules are binding. If a rule blocks progress, change the plan in writing (PHASES.md or this file) before breaking it. Do not break it silently.

## Data

1. The test fold is never used for tuning, early stopping, feature selection, or any other decision. Decisions use the inner validation split only. The residual overlap (inner validation sets contain videos that are test videos in other folds) is disclosed in the README.
2. LIVE-VQC is not used for predictions until the KoNViD-1k config is frozen. Extracting its features earlier is allowed. Looking at LIVE-VQC results and then changing the model is test-set selection, and it is not allowed.
3. YouTube-UGC is cut from the 10-day scope. If explicitly reinstated, its subset is chosen from metadata only (category and MOS bin, fixed seed, 720p and 1080p originals only), and its video IDs are saved to the repo before any extraction or evaluation. The subset is not changed after seeing results. Clips that fail to download or decode are logged by ID and reported, never silently dropped.
4. Fold and inner-validation indices are generated once and committed. They are never regenerated. If they must change, the change is logged and all results are re-run.
5. Dataset licenses are checked before publishing. Videos are never committed to the repo.
6. Raw videos may be deleted after features are cached. Before deleting, confirm that the cache checksums match the manifest. If YouTube-UGC is explicitly reinstated, each clip is downloaded, verified (size and decode), featurized, synced, and deleted before the next one; frames are never streamed from a URL.

## Experiments

7. All heads run under the same protocol: same folds, same seeds, same loss (L1 on z-scored MOS plus a pairwise rank term with one shared weight), same optimizer and schedule, same tuning budget, and head-only trainable parameter counts within about 5 percent across the GRU, Transformer, and Mamba heads for each feature set. Total parameter counts are reported too. The mean-pool MLP is matched where feasible, and otherwise its count is reported.
8. Hyperparameters are tuned once, on fold 0, with an inner validation split. The rank-loss weight is tuned first with the mean-pool head and frozen before any head is tuned. The tuned configs are then frozen. Per-fold or per-seed tuning is not allowed. Tuning uses one fixed feature set (DINOv2 last-layer CLS plus block-12 mean-patch). The frozen configs are reused on other feature sets without re-tuning, and the README says so.
9. Every reported accuracy experiment runs with 5 seeds. A result from one seed is not reported on its own, except the deployed checkpoint (seed 0), which is always shown next to the 5-seed summary. Seeds change initialization and batch order only; the inner validation split is fixed per fold. Deterministic models (ridge regression) run once. Tuning trials are selection work, not reported accuracy results: they default to five seeds, but a measured Phase 1 Task 7 no-go may reduce rank/head tuning to fixed seeds [0,1], equally for all heads and logged in DECISIONS.md before tuning. This exception never reduces five-seed CV, generalization or shuffled-label controls.
10. A shuffled-label control runs with every new pipeline change. It passes when the 95% bootstrap CI of its SRCC includes zero and its absolute SRCC is below 0.15. If it fails, stop and find the leak before going further. It is run on fold 0 with the cheapest head, not across the full grid.
11. Ridge regression on mean-pooled features is always reported as Baseline 0. If a neural head does not beat it, that is reported as a finding, not hidden.
12. Causal and bidirectional variants are never mixed in the same comparison. Bidirectional is the primary Mamba configuration. Causal is a labeled side experiment.
13. Every head handles padding through masking, and bidirectional heads reverse each sequence within its valid length. No head may see padded timesteps as signal. A padding-invariance unit test must pass for every head.
14. Feature choice (Phase 2) is made on mean inner-validation SRCC across folds and seeds, never on held-out fold results. The head comparison is run afterward on the chosen feature set. State in the README that selection used inner-validation scores drawn from the same KoNViD videos as the head comparison. Under the 10-day scope, the separate DINOv2 layer comparison is skipped. The declared DINO representation is last-layer CLS plus block-12 patch mean; blocks 6/9/12 mean/std are still cached, without a layer-improvement claim. Feature selection compares only this fixed DINO representation and the ResNet-50 control using inner-validation scores. The set of cached layers is decided before extraction.

## Statistics and Reporting

15. Every number in the README and in any resume or document is generated by a script from saved outputs. No numbers are typed by hand.
16. Differences between heads are reported with paired 95% bootstrap confidence intervals over videos and classified with the decision table in PRD.md section 7: equivalent within margin; A better than B (practically meaningful); detectable difference, not shown to exceed the margin; or no detectable difference (inconclusive). Classification is checked in that order.
17. The wording "X beats Y" is used only for the "practically meaningful" category. The "detectable difference" category is worded as "X higher than Y, detectable but not shown to exceed the margin." A difference whose CI includes zero is worded as "no detectable difference."
18. Mean and standard deviation are reported across seeds and folds, separately from the bootstrap CIs. The headline table uses mean per-fold SRCC; the bootstrap uses the seed-averaged pooled ensemble. Both are labeled. Bootstrap CIs capture test-set noise only and are described as applying to the seed-averaged ensemble.
19. Negative results are reported with the same prominence as positive ones. A tie between heads is a valid headline.
20. PLCC on LIVE-VQC is computed after a 4-parameter logistic fit, and this is stated in the README. SRCC and KRCC are reported without mapping. PLCC is not bootstrapped.
21. Published SOTA numbers are cited from their original papers, with the exact split and protocol noted. Gaps are explained with reasons (for example, end-to-end training versus cached features, input resolution, temporal sampling), not asserted.
22. No README or resume number is written until the corresponding result exists in results/.
23. Frame-level quality scores are labeled weakly supervised everywhere they appear, because the datasets have only video-level MOS.

## Preprocessing and Reproducibility

24. The preprocessing policy in ARCHITECTURE.md (both the spatial and the motion branch) is frozen. Any change creates a new cache version and re-runs all dependent experiments.
25. Offline, serving, and cloud-notebook code import the same preprocess.py and features.py. Duplicating these files is not allowed.
26. Every run logs its config hash, seed, fold, code commit, cache version, locked environment hash, and checkpoint hash.
27. Seeds are fixed for Python, NumPy, and PyTorch.

## Serving and Deployment

28. The deployed checkpoint is the Phase 3 model trained on all of KoNViD-1k with the chosen configuration, seed 0. Its hash is checked at startup.
29. Latency is measured on CPU per stage and reported in the README.
30. Serving does not change the model. The deployed configuration is the reported configuration with the highest headline KoNViD CV SRCC that meets the CPU latency budget recorded in DECISIONS.md. A spatial-only configuration is acceptable, provided it is one of the reported feature-set rows. No separately quantized or toggled variant is deployed unless it was itself evaluated and reported.
31. Uploaded videos are deleted after processing or kept only under a stated retention limit.

## Scope

32. Work proceeds in phase order. A later phase does not begin until the earlier phase's exit criterion is met.
33. When time or disk is short, cut features in the order in PHASES.md. Never cut the shuffled-label control, the confidence intervals, the LIVE-VQC test, the parity checks, or the honest README.
34. Dashboard features are added only after the evaluation is complete. Model and evaluation work takes priority over UI work.

## Documentation

35. Every decision that changes the plan is recorded with a date in a DECISIONS.md log, including what was changed and why.
36. The README states what was not done and why (for example, YouTube-UGC skipped, or features not extracted at 8 fps).

## Compute Location and Parity

37. All extraction, training, and evaluation run locally. YouTube-UGC and cloud work are cut from the 10-day scope. Reintroducing cloud work requires a dated DECISIONS.md entry.
38. Cloud parity is inactive while UGC is cut. If UGC is explicitly reinstated, the notebook must install the same lock and import the same src/ code; the 10-video KoNViD cloud parity threshold (cosine at least 0.999 per timestep) must pass before any UGC extraction.
39. The serving parity check (20 videos, CPU fp32 against cached GPU fp16) must pass before Phase 4 is complete, and its numbers are reported in the README.
40. The decoder applies rotation metadata. A video whose orientation cannot be determined is logged and reported, not silently cropped.
41. Holm-adjusted p-values are reported for the primary comparison families (head pairs on KoNViD, head pairs on LIVE-VQC). All other comparisons are labeled secondary and unadjusted.
